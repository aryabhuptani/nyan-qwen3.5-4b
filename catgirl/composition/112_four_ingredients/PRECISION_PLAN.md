# Prospective numerical sensitivity audit

This audit was specified after discovery-only GPU integrity checks and before held-out validation results were read. That implementation audit found full-versus-cached BF16 numerical differences, including a maximum 0.08984 difference in a Yes/No intervention contrast. The observation motivates checking numerical stability; it is not evidence that any particular small effect is numerical noise.

After all forecasting sessions are locked, run **all 12 held-out lexical-writing cases**, without selecting favorable cases. For each case evaluate baseline and that case's matched ingredient's frozen enhancement and median attenuation: 36 condition-case rows and both continuations in every row. Use the generation-scope operations copied unchanged from `jobs/JOB_validation_lexical_generation.json`. Frozen endpoints and fractions remain those selected from BF16 discovery data.

Load the identical pinned original BF16 checkpoint, then cast every floating model parameter to float32 before inference; BF16 values are exactly representable in float32. No new checkpoint, dose fitting, altered tokenization, changed continuation or validation-based parameter selection is allowed. Reuse the actual frozen `Probe` class by AST extraction and the same canonical tokenizer helper. Use unchunked teacher-forced forwards with no cache, matching the original lexical scoring path. All floating model parameters and hook inputs must be float32. Kernel implementation is MLX's float32 path; this does not establish exact real-number arithmetic or cross-hardware numerical agreement.

Record all target/control per-token, sum and mean log probabilities and achieved native scalar values. Compare the intervention-minus-baseline change in target-minus-control **mean-token** log probability between float32 and BF16, reporting every one of the 24 matched intervention contrasts. Report mean and maximum absolute discrepancy, sign agreement including exact-zero counts, each ingredient separately, and all raw values. No sign-consistency or discrepancy threshold is used to select or discard cases or to redefine the main outcomes. Small BF16 effects that reverse or change substantially should be described as numerically fragile; surviving effects remain limited to this fixed checkpoint, dataset, intervention and precision comparison.

This is a declared sensitivity analysis, not an independent replication or a replacement for the frozen primary BF16 results. The audit script refuses a GPU run without an existing forecast-lock artifact and retains its hash. The root agent alone runs GPU inference. Keep all outputs and numerical failures.
